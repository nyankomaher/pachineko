# TOP画面 仕様書

## 概要

TOP画面は **「記録開始のハブ」** である。UC1（遊戯実績の記録）を開始するための入口を最優先の導線とし、それ以外の画面（履歴・分析・設定・店舗一覧・機種一覧）へはグローバルナビゲーション（後述）からのみ遷移する。ダッシュボード的な集計サマリーや履歴一覧は TOP には置かない（それらは「履歴」「分析」タブの役割）。

## 対象デバイス・レイアウト方針

- **記録（UC1）はスマートフォン利用を最優先**とする。遊技中に片手で操作できるレイアウトにする。
- 分析（UC2）は PC での閲覧も同等に重視するため、レスポンシブ対応は必須だが、TOP画面自体はモバイルファーストで設計する。
- **PWA化する**（ホーム画面に追加してアプリのように起動できるようにする。`manifest`・アイコン等が必要 — 実装時に `@vite-pwa/nuxt` 等の採用を検討）。

## 画面構成

### ナビゲーション（共通レイアウト）

画面右上固定のトグルボタンで開閉する、左からスライドして表示するグローバルナビゲーション（PrimeVueの`Drawer`）を採用する。普段は非表示で、トグルボタンをタップすると表示され、再度タップ、またはリンクの選択で閉じる。

ナビゲーション一覧の先頭には、記録中セッションの有無に応じて次のいずれかのボタンを表示する。

- 記録中セッションが存在する場合: 「記録継続」ボタン。押下すると `/records/[recordId]/create`（記録中セッションが対象とする実績の区間実績詳細画面・新規入力）に遷移する（業務フロー「区間実績記録再開（トップ画面）」と同様の遷移先）。
- 記録中セッションが存在しない場合: 「記録開始」ボタン。押下時の挙動はTOP画面の「記録開始」ボタン（後述）と同じで、`/records/create` に遷移する。

| 項目 | 内容 |
|---|---|
| TOP | 本仕様の画面。記録開始のハブ |
| 履歴 | UC2: 記録データの一覧表示 |
| 収支カレンダー | UC2: 収支を1ヶ月分のカレンダー形式で日別に表示（`specs/calendar.md` 参照） |
| 分析 | UC2: 月別・日別・台別などの集計表示 |
| 設定 | 交換レートの選択肢を管理する（`specs/settings.md` 参照。UC3/UC4のエクスポート・インポートは別画面で提供予定、`specs/settings.md` 参照） |
| 店舗一覧 | 店舗の一覧表示・並び替え・新規登録（`specs/halls-list.md` 参照） |
| 機種一覧 | 機種の一覧表示・並び替え・新規登録（`specs/machines-list.md` 参照） |

各項目の中身（TOP以外）は本仕様のスコープ外。グローバルナビゲーションからの遷移先として存在することのみ定義する。

分析画面を除き、コンテンツ幅は最大768pxに制限し画面中央に表示する（`CLAUDE.md` アーキテクチャ参照）。

### TOP画面のコンテンツ

TOP画面は状態によって以下の2パターンの表示になる。

#### (a) 記録中セッションが「ない」場合

- 大きな「記録開始」ボタンのみを中心に配置したシンプルな画面。
- データの有無（初回起動かどうか）によって表示を変えない。空状態でも通常時と同じ「記録開始」ボタンのみのレイアウトで統一する。

#### (b) 記録中セッションが「ある」場合

- 「記録開始」ボタンは**非表示**にする（同時記録は常に1台のみのため）。
- 代わりに **記録中カード** を表示する。カードをタップすると記録中の入力画面（UC1本編、本仕様スコープ外）に遷移し、記録を継続できる。

**記録中カードの表示項目:**

- 機種名
- 台番号
- 経過時間
- 投資金額: 「投資金額 + 投資玉数 = 実質投資額」の形式で表示する（`CLAUDE.md` 用語定義「実質投資額」参照。投資玉数が負の場合は「+」を「-」に置き換える）
- 回転数: 「回転数 (1000円あたり回転数)」を1行にまとめて表示する（例:「1,000回転 (20.0回転)」、`specs/record-detail.md` の集計情報セクションと同様の形式）

経過時間・投資金額・回転数は、いずれも `CLAUDE.md` 用語定義の「総〜」項目（画面表示時は「総」を付けない）であり、このセッションの記録開始時点から現在までの区間記録をすべて合算・算出した値（UC1の「この台の遊戯開始からの同様のデータ」に相当）である。直近の区間だけのスナップショットではない。

### ページ内メニュー

「記録開始」ボタン（状態a）または記録中カード（状態b）の下に、グローバルナビゲーション（前述）と同じ遷移先一覧のうち、TOPを除いたもの（履歴・分析・設定・店舗一覧・機種一覧）をメニューとして常時表示する。TOP画面上では「TOP」へのリンクは意味を持たないため含めない。コンポーネントとしての共通化は行わず、TOP画面側で個別に実装する。

「記録開始」ボタンは本アプリケーションの主導線であるため、ボタン（またはカード）とこのメニューとの間には大きめのマージンを取り、ボタン側の視覚的な優先度を保つ。

### 記録開始フロー

「記録開始」ボタン押下 → `/records/create`（実績詳細画面の新規作成用URL。台番号・機種名などを入力、詳細は `specs/record-detail.md` 参照、本仕様スコープ外）に遷移。この時点ではDB書き込み・記録中セッションの開始は行わない。実績詳細画面側で入力確定・記録開始操作を行った時点で初めて記録（タイマー）が開始し、TOP画面は (b) の状態になる。

## 状態管理・永続化方針

### グローバル状態: Pinia

「記録中セッションの有無・内容」は Pinia store でアプリ全体から参照できるグローバル状態として保持する。TOP画面はこの store を参照して (a)/(b) の表示を切り替える。

### 記録中セッションの永続化: LocalStorage

当初「記録中状態はメモリ（Pinia）のみで保持し、アプリ終了で記録も終了とみなす」という案を検討したが、**ページリロードやタブの閉じ直しで記録中データが消えるリスクを避けるため、記録中セッションは LocalStorage にミラーリングして永続化する**方針とする。

- 確定済みの履歴データ（UC1完了後のレコード）は Dexie（IndexedDB）に保存する（`CLAUDE.md` の既定方針どおり）。
- **記録中（未確定）のセッションのみ** LocalStorage に保存する。IndexedDB を使わない理由: 記録中セッションは単一の小さな JSON オブジェクトであり、同期API で読み書きできる LocalStorage の方が Dexie の非同期クエリより実装がシンプルなため。
- Pinia store は起動時に LocalStorage から記録中セッションを復元（hydrate）し、以後は状態が変化するたびに LocalStorage に書き戻す。
- アプリ起動時（ページロード時）に LocalStorage に記録中セッションが存在すれば、自動的に (b) の状態として TOP画面に反映される。

### 同時記録数

常に1台のみ。複数台の並行記録には対応しない。記録中に「記録開始」ボタンを再度使うことはできない（ボタン自体を非表示にすることで制約をUI上も明確にする）。

## UI/デザインシステム

**PrimeVue** をアプリ全体のデザインシステムとして採用する。

- 採用理由: 「履歴」タブの表形式表示（DataTable）と「分析」タブのグラフ表示（Chart, Chart.js ラッパー）を、追加のチャートライブラリ選定なしに単一のコンポーネントライブラリで賄えるため。TOP画面のカード・ボタン類も PrimeVue の Card / Button / Badge 等で統一する。
- Nuxt との統合は公式 Nuxt モジュール `@primevue/nuxt-module` を使用する想定（導入自体は本仕様のスコープ外、実装フェーズで対応）。
- テーマ・配色（プリセットテーマの選定、ダークモード対応）は実装フェーズで別途提案する。
- TOP画面で使う想定コンポーネント: `Card`（記録中カード）、`Button`（記録開始ボタン）。グローバルナビゲーションは前述の`Drawer`を使用する（下部タブバーは採用しない）。

## スコープ外・今後の検討事項

- **IndexedDB / LocalStorage が使えない環境**（プライベートブラウジングの制限、ストレージ容量超過など）への対応は今回の仕様では考慮しない。
- 複数タブを同時に開いた場合の記録中セッションの同期（タブ間の整合性）は非対応。後勝ち上書きの挙動になる想定だが、対策は行わない。
- 台情報入力画面（記録開始フローの遷移先）の詳細フィールド仕様は別途 UC1 の仕様として定義する。
- 履歴・分析・設定タブの画面仕様は別途定義する。
- PrimeVue の具体的なテーマ・配色（ダークモード含む）は実装フェーズで別途提案する。
