# 実績詳細画面 仕様書

## 概要

実績詳細画面は、1つの実績（1台の遊戯開始〜終了の記録）の基本情報と、その実績に属する区間実績の一覧を表示・編集する画面である。また、`CLAUDE.md` の業務フローに定義された「記録開始」「記録再開」「記録終了」の各操作の起点にもなる、記録フローの中心的なハブ画面である。

新規作成用の `/records/create` と、既存実績の編集用 `/records/[recordId]` の2つのURLを持つ（ルーティングの詳細は後述）。

## ルーティングに関する補足

`specs/period-detail.md` と同様のパターンを採る。新規の実績はまだIDを持たないため、TOP画面の「記録を始める」ボタンからは `/records/create` に遷移する。既存の実績を一覧・詳細画面から開く場合は `/records/[recordId]` に遷移する。Nuxt のファイルベースルーティングでは、静的セグメント（`create.vue`）は動的セグメント（`[recordId].vue`）より優先して解決されるため、両者は問題なく共存できる。

## 前提知識: 実績と区間実績の作成タイミング

- TOP画面の「記録を始める」ボタン押下時点ではDBへの書き込み・記録中セッションの開始は行わない（`specs/top-screen.md` 参照）。`/records/create` に遷移し、本画面で日付・店舗・機種・台番号などの基本情報を入力した上で「記録開始」ボタンを押下した時点で、初めて実績テーブルに1行を作成し、記録中セッションを生成する（`CLAUDE.md` 業務フロー「実績記録開始」）。作成後は `/records/[recordId]/create`（区間実績詳細の新規入力）に遷移する。
- 区間実績は「記録」ボタン押下時に初めて区間実績テーブルへ保存される（区間実績詳細画面 `specs/period-detail.md` 参照）。したがって、実績作成直後に本画面（`/records/[recordId]`）を訪れた場合、区間実績が0件のことがある（例: 記録開始直後に区間実績詳細画面から下部タブで本画面に戻った場合）。

## 画面構成

### 基本情報セクション

実績テーブルのうち、区間ごとに変化しない項目を表示・編集する。

| 項目 | 種別 |
|---|---|
| 日付 | 入力（日付ピッカー） |
| 店舗 | 入力（プルダウン。事前に店舗テーブルへ登録済みの店舗のみ選択可能。横に新規登録用の「＋」ボタンを配置） |
| 機種 | 入力（既存の機種テーブルからの選択、または新規機種名の入力） |
| 台番号 | 入力（数値） |
| 交換レート | 入力（数値、円/玉） |

- 店舗は店舗テーブルへの外部キー参照のため、プルダウン（`Select`）で事前登録済みの店舗のみを選択可能とする（`specs/halls-list.md` の表示順で選択肢を並べる）。機種とは異なり、自由入力によるその場での店舗登録は行わない。
- 店舗プルダウンの横に「＋」アイコンボタンを配置する。押下すると店舗詳細画面のフォームコンポーネント（`specs/hall-detail.md` 参照）をモーダル（`Dialog`）で表示する。モーダル内で店舗を登録すると、モーダルが閉じてプルダウンの選択肢が更新され、登録した店舗が選択された状態になる（`CLAUDE.md` 業務フロー「店舗新規登録（実績詳細から）」）。
- 機種は従来通り、店舗テーブルとは異なり選択式（オートコンプリート等）で既存のものを選べるようにしつつ、未登録の機種名を入力した場合はテーブルへ新規追加する（本仕様変更の対象外）。
- 交換レートは店舗ではなく実績ごとに保持する項目であり（`CLAUDE.md` 用語定義「交換レート」参照）、店舗テーブルには存在しない。同じ店舗でもレート変動イベント等により実績ごとに異なりうるため、都度この画面で入力する。新規作成時の初期値は `4`（最も一般的な交換レート）とする。必須入力とする。現時点ではみなし投資金額の計算（`CLAUDE.md` 用語定義「みなし投資金額」、現状は店舗・実績によらず4円固定で計算）には使用せず、記録のみを行う。
- `/records/[recordId]`（既存実績の編集）では「修正」ボタン押下で上記の変更を実績テーブルへ保存する（`CLAUDE.md` 業務フロー「実績修正」）。
- `/records/create`（新規作成）では、同じ入力項目を「記録開始」ボタンで確定する。押下時に実績テーブルへ新規行を作成し、記録中セッションを開始した上で `/records/[recordId]/create` に遷移する（上述「前提知識」参照）。この画面にはまだ集計情報・区間実績一覧は存在しない（区間実績が1件も無いため）。

### レイアウト

- 日付は単独の行とする（店舗とは横並びにしない）。
- 店舗はプルダウンと「＋」ボタンを同一行に横並びで配置する単独の行とする。
- 機種は単独の行とする。
- 台番号・交換レートは横並びとする。
- 開始時刻・終了時刻は横並びとする。

### 集計情報セクション（表示のみ、`/records/[recordId]` のみ）

実績テーブルに保持する「総〜」項目を、画面表示時は「総」を付けずに表示する（`CLAUDE.md` 用語定義に準拠）。

- 経過時間（開始時刻〜終了時刻、または記録中は開始時刻〜現在時刻）
- 投資金額
- 投資持玉
- 最終持玉
- 回転数
- 1000円あたり回転数
- RUSH当選数 / 通常当選数 / チャージ当選数
- 連荘数
- 獲得玉数

これらは、この実績に属する全区間実績を集計して算出する値であり、区間実績の記録・修正・削除の都度、実績テーブル側の該当フィールドに再計算・保存する（非正規化して保持する。`CLAUDE.md` の実績テーブルスキーマに準拠）。

### 区間実績一覧セクション

この実績に属する区間実績を、開始時刻の昇順で一覧表示する（表形式、`DataTable` を使用）。

| 列 | 内容 |
|---|---|
| 開始時刻〜終了時刻 | 区間の時間帯 |
| 投資金額 | 区間実績の投資金額 |
| 回転数 | 終了回転数 - 開始回転数 |
| 1000円あたり回転数 | この区間単体の値 |
| 当選種別 | RUSH/通常/チャージ/なし |
| 連荘数 | 区間実績の連荘数 |

各行をタップ/クリックすると区間実績詳細画面（`/records/[recordId]/[periodId]`）に遷移し、その区間実績を編集できる（`CLAUDE.md` 業務フロー「区間実績修正」）。

### 記録操作ボタン

記録中セッションの状態に応じて、以下のように表示を出し分ける。

| 状態 | 条件 | 表示するボタン | 挙動 |
|---|---|---|---|
| A: 未記録 | 記録中セッションが存在しない | 「記録再開」 | 押下でこの実績を対象とする記録中セッションを新規生成し、区間実績詳細画面（新規入力）に遷移する（業務フロー「実績記録再開」） |
| B: 記録中・初回区間未入力 | 記録中セッションが存在し、対象実績IDがこの画面のものと一致し、かつ区間実績が0件 | 「記録開始」＋「削除」 | 「記録開始」押下で区間実績詳細画面（新規入力）に遷移する。セッションは既に生成済みのため新規生成はしない（業務フロー「実績記録開始」ステップ5）。「削除」押下で記録中セッションを破棄し、トップ画面に戻る |
| C: 記録中・区間入力済み | 記録中セッションが存在し、対象実績IDがこの画面のものと一致し、かつ区間実績が1件以上 | 「記録再開」＋「記録終了」 | 「記録再開」押下で区間実績詳細画面（新規入力）に遷移（業務フロー「区間実績記録再開（実績詳細画面）」）。「記録終了」押下で記録中セッションを破棄する（業務フロー「実績記録終了」）。破棄後は画面の状態をAに更新する |
| D: 他の実績を記録中 | 記録中セッションが存在するが、対象実績IDがこの画面のものと異なる | 記録操作ボタンは非表示 | 同時記録数は常に1台のみのため（`specs/top-screen.md` 参照）、この画面では記録の開始・再開はできない。閲覧・修正のみ可能 |

### 削除

実績を削除するボタンを提供し、押下時に確認ダイアログを表示する。削除確定時は、この実績に属する区間実績もすべて連動して削除する（カスケード削除）。

## データアクセス

- 実績1件と、それに属する区間実績一覧を Dexie から取得する（区間実績テーブルは実績ID にインデックスが張られているため、これで絞り込む）。
- 店舗プルダウンの選択肢は、店舗テーブルを表示順（`order`）昇順で取得する（`specs/halls-list.md` 参照）。モーダルでの新規登録後は再取得する。
- 集計値（総〜項目）の再計算ロジックは区間実績詳細画面（`specs/period-detail.md`）と共通の計算コンポーザブルとして実装し、両画面から利用する。

## スコープ外・今後の検討事項

- 機種の新規登録時の重複防止（表記ゆれ対策など）は本仕様では扱わない（店舗は事前登録制のため対象外）。
- 交換レートを、みなし投資金額の計算（現状は店舗・実績によらず4円固定で計算）に反映するかどうかは別途検討する。
