# 区間実績詳細画面 仕様書

## 概要

区間実績詳細画面（`/records/[recordId]/[periodId]`）は、UC1（遊戯実績の記録と回転数の分析）の中心となる画面である。遊技中に任意の区間（投資と回転数の記録単位）を入力・記録し、その区間の1000円あたり回転数と、この実績（台）の遊戯開始からの総1000円あたり回転数の両方をその場で表示する。

また、既存の区間実績を選択して修正する場合（`CLAUDE.md` 業務フロー「区間実績修正」）にも同じ画面を使う。

## ルーティングに関する補足

`CLAUDE.md` のサイトマップは `/records/[recordId]/[periodId]` の1行のみを定義しているが、新規の区間実績はまだIDを持たない（区間実績テーブルへの保存は「記録」ボタン押下時に行われるため）。実装では新規入力用に `/records/[recordId]/create` を追加し、既存区間の編集には `/records/[recordId]/[periodId]` を使う想定とする（`/records/create` の命名と統一）。Nuxt のファイルベースルーティングでは、静的セグメント（`create.vue`）は動的セグメント（`[periodId].vue`）より優先して解決されるため、両者は問題なく共存できる。

## 画面構成

### 入力フォーム

区間実績テーブルの各フィールドに対応する入力欄を、以下のグループで構成する。

**時刻**
- 開始時刻: 新規入力時は、この実績の直前の区間実績の終了時刻（無ければ実績の開始時刻）を初期値とする
- 終了時刻: 新規入力時は現在時刻を初期値とする

**投資・持玉**
- 投資金額
- 開始持玉 / 終了持玉
- 開始貸玉 / 終了貸玉

**回転数**
- 開始回転数 / 終了回転数

**当選**
- 当選種別（なし / ST / 通常 / チャージ の選択。実績テーブルのST当選数・通常当選数・チャージ当選数の集計元になる）
- ST継続数（当選種別がSTの場合に入力）
- 獲得玉数
- 当選後持玉 / 当選後貸玉（`CLAUDE.md` 用語定義「当選による持玉/貸玉の増加を加算した後の持玉/貸玉」）

新規入力時は、開始持玉・開始貸玉・開始回転数は、この実績の直前の区間実績の終了持玉・終了貸玉・終了回転数を初期値として引き継ぐ（無ければ0または未入力）。

### リアルタイム計算表示

入力内容から以下を都度計算し、画面に表示する（UC1「1000円あたりの回転数を表示する」「この台の遊戯開始からの同様のデータも表示する」に対応）。

| 表示項目 | 算出方法 |
|---|---|
| この区間の回転数 | 終了回転数 - 開始回転数 |
| この区間のみなし投資金額 | `CLAUDE.md` 用語定義: 投資金額 + ((開始持玉 - 終了持玉) + (開始貸玉 - 終了貸玉)) × 4 |
| この区間の1000円あたり回転数 | この区間の回転数 / (この区間のみなし投資金額 / 1000) |
| 総回転数（この区間を含む） | 実績に既存の総回転数 + この区間の回転数 |
| 総1000円あたり回転数（この区間を含む） | 実績に既存の集計 + この区間の値を合算して算出 |

計算ロジックは `specs/record-detail.md` と共通のコンポーザブルとして実装する。

### アクション

**新規記録の場合**
- 「記録」ボタン: 区間実績テーブルへ新規保存し、実績テーブルの集計フィールドを再計算・更新する。保存後、「継続する/終了する」ダイアログを表示する（業務フロー「区間実績記録 / 実績記録終了」）。
  - 継続する: 入力内容をクリアし、次の区間実績の入力が可能な状態にする（画面遷移はしない、または `/records/[recordId]/create` に留まる）。
  - 終了する: 記録中セッションを破棄し、実績詳細画面に遷移する。
- 「キャンセル」ボタン: 確認ダイアログを表示する（業務フロー「区間実績記録キャンセル」）。
  - キャンセルする: 実績詳細画面に遷移する（未保存の入力内容は破棄）。
  - キャンセルしない: この画面に留まる。

**既存区間の修正の場合**
- 「修正」ボタン: 区間実績テーブルの該当行を更新し、実績テーブルの集計フィールドを再計算・更新した上で、実績詳細画面に遷移する（継続/終了ダイアログは表示しない。記録中フローとは異なる操作のため）。
- 「削除」ボタン: 確認ダイアログの上、この区間実績を削除し、実績テーブルの集計フィールドを再計算・更新した上で、実績詳細画面に遷移する。

## 状態管理・永続化方針

- 記録中セッション（Pinia store、`specs/top-screen.md` 参照）から対象の実績IDを取得する。
- 新規記録時の未保存の入力内容自体は、他の画面同様 Pinia のメモリ状態で保持する。ページリロード時に入力途中のデータまで復元するかどうかは、記録中セッションのLocalStorageミラーリング方針（`CLAUDE.md` 用語定義「記録中セッション」）の対象を実績ID等の最小限の情報に留めるか、フォーム入力内容まで含めるかによって決まるため、実装フェーズで確定する。

## スコープ外・今後の検討事項

- 未保存の入力内容そのものをリロード後も復元するかどうか（上述）。
- 当選種別が複数回発生した場合の入力方法（1区間内で複数当選が起きた場合の扱い）は本仕様では扱わない。
