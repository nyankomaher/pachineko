# 区間実績詳細画面 仕様書

## 概要

区間実績詳細画面（`/records/[recordId]/[periodId]`）は、UC1（遊戯実績の記録と回転数の分析）の中心となる画面である。遊技中に任意の区間（投資と回転数の記録単位）を入力・記録し、その区間の1000円あたり回転数と、この実績（台）の遊戯開始からの総1000円あたり回転数の両方をその場で表示する。

また、既存の区間実績を選択して修正する場合（`CLAUDE.md` 業務フロー「区間実績修正」）にも同じ画面を使う。

## ルーティングに関する補足

`CLAUDE.md` のサイトマップは `/records/[recordId]/[periodId]` の1行のみを定義しているが、新規の区間実績はまだIDを持たない（区間実績テーブルへの保存は「記録」ボタン押下時に行われるため）。実装では新規入力用に `/records/[recordId]/create` を追加し、既存区間の編集には `/records/[recordId]/[periodId]` を使う想定とする（`/records/create` の命名と統一）。Nuxt のファイルベースルーティングでは、静的セグメント（`create.vue`）は動的セグメント（`[periodId].vue`）より優先して解決されるため、両者は問題なく共存できる。

## 画面構成

### 入力フォーム

区間実績テーブルの各フィールドに対応する入力欄を、以下のグループで構成する。

**時刻**
- 開始時刻: 新規入力時はこの画面を開いたときの時刻を初期値とする
- 終了時刻: 新規入力時は未入力とする。記録ボタン押下時に未入力であれば、現在時刻とする（その旨の注釈を表示）

**投資・持玉**
- 投資金額
- 開始持玉 / 終了持玉
- 開始貸玉 / 終了貸玉

**回転数**
- 開始回転数 / 終了回転数

**当選**
- 当選種別（なし / RUSH / 通常 / チャージ の選択。実績テーブルのRUSH当選数・通常当選数・チャージ当選数の集計元になる）
- 連荘数
- 出玉
- 当選後持玉 / 当選後貸玉（`CLAUDE.md` 用語定義「当選による持玉/貸玉の増加を加算した後の持玉/貸玉」。手入力）

当選種別に応じて、連荘数〜当選後貸玉（連荘数・出玉・当選後持玉・当選後貸玉）を次のように制御する。

| 状況 | 挙動 |
|---|---|
| 当選種別が「なし」（画面表示時の初期値が「なし」の場合を含む） | 連荘数〜当選後貸玉を非活性にする |
| 「なし」以外に変更した時点 | 連荘数〜当選後貸玉を活性にする。連荘数が1未満（未入力・0など）であれば1を設定する（既に1以上なら変更しない）。当選後持玉・当選後貸玉が未入力であれば0を設定する（既に入力されている場合は変更しない。例: RUSH→通常の変更） |
| 「なし」に戻した時点 | 連荘数〜当選後貸玉の入力値を破棄し、初期値（連荘数0、出玉0、当選後持玉・当選後貸玉は未入力）に戻す |

当選セクションはアコーディオン（`Accordion`）で開閉可能にし、見出しを「当選」とする。初期状態は、当選種別が「なし」の場合は閉じた状態、「なし」以外（既存区間の修正で当選が記録済みの場合）は開いた状態とする。

画面上のセクション表示順は 時刻 → 投資・持玉 → 回転数 → （リアルタイム計算表示、後述） → 当選（アコーディオン） → 記録/修正ボタン の順とする。記録/修正ボタンは1つのみ配置する。

新規入力時は、開始持玉・開始貸玉・開始回転数は、この実績の直前の区間実績の終了持玉・終了貸玉・終了回転数を初期値として引き継ぐ（無ければ0）。
ただし、前回の当選種別がRUSH or 通常の場合は開始回転数は未入力とする。当選種別にかかわらず、当選後持玉・当選後貸玉が入力されている場合はそちらを引き継ぐ（開始持玉・開始貸玉それぞれ個別に判定する）。
終了持玉、終了貸玉は開始持玉、開始貸玉を初期値とする。

### リアルタイム計算表示

入力内容から以下を都度計算し、画面に表示する（UC1「1000円あたりの回転数を表示する」「この台の遊戯開始からの同様のデータも表示する」に対応）。

| 表示項目 | 算出方法 |
|---|---|
| 区間投資 | `CLAUDE.md` 用語定義「区間投資」参照。「投資金額 + 投資玉数 = 実質投資額」の形式で表示する（例: 3,000円 + 1,000玉 = 6,500円）。投資玉数が負の場合は「+」を「-」に置き換える |
| 区間回転数（かっこ書きで1000円あたり回転数を併記） | 回転数 = max(0, 終了回転数 - 開始回転数)。1000円あたり回転数 = 回転数 / (みなし投資金額 / 1000)（`CLAUDE.md` 用語定義「みなし投資金額」「1000円あたり回転数」参照。区間投資の実質投資額とは別の値で、みなし投資金額は交換レートによらず4円固定で算出する） |
| 総投資（この区間を含む） | 区間投資と同じ形式（「総投資金額 + 総投資玉数 = 総実質投資額」）で、この実績のうちこの区間より前（開始時刻昇順）の区間実績の投資金額・投資玉数の合計にこの区間の投資金額・投資玉数を加えた値を表示する |
| 総回転数（かっこ書きで総1000円あたり回転数を併記、この区間を含む） | 総回転数 = この区間より前（開始時刻昇順）の区間実績の回転数の合計 + この区間の回転数。総1000円あたり回転数はみなし投資金額と同様の考え方で総回転数・総みなし投資金額から算出する |

回転数は終了回転数が開始回転数を下回る入力ミス等があっても0未満にはならないよう、下限0でクランプする。

この4項目を枠で囲んで表示し、その直後に当選セクション（アコーディオン）、記録/修正ボタンの順に配置する（前掲「画面上のセクション表示順」参照）。

計算ロジックは `specs/record-detail.md` と共通のコンポーザブルとして実装する。

### アクション

**新規記録の場合**
- 「記録」ボタン: クリック時点ではまだ区間実績テーブルへの保存は行わず、「継続する/終了する」ダイアログを表示する（業務フロー「区間実績記録 / 実績記録終了」）。ダイアログの選択後に初めてDBへの保存が行われる。
  - 継続する: 区間実績テーブルへ新規保存し、実績テーブルの集計フィールドを再計算・更新する。入力内容をクリアし、次の区間実績の入力が可能な状態にする（画面遷移はせず `/records/[recordId]/create` に留まり、画面最上部にスクロールする）。
  - 終了する: 直近の区間実績の貸玉（当選後貸玉が入力されていればそちら、なければ終了貸玉）が0であることを検証する。0でなければダイアログ内にエラーメッセージを表示して中止する。0であれば区間実績テーブルへ新規保存し、実績テーブルの集計フィールドを再計算・更新した上で、実績の終了時刻を現在時刻で記録し、収支（`CLAUDE.md` 用語定義「収支」参照）を算出して記録した上で記録中セッションを破棄し、実績詳細画面に遷移する。
- 「キャンセル」ボタン: 確認ダイアログを表示する（業務フロー「区間実績記録キャンセル」）。ダイアログのボタンは「はい」（キャンセルする）/「いいえ」（キャンセルしない）とする。
  - はい: 実績詳細画面に遷移する（未保存の入力内容は破棄）。
  - いいえ: この画面に留まる。

**既存区間の修正の場合**
- 「戻る」ボタン: 確認なしで実績詳細画面に遷移する。
- 「修正」ボタン: 区間実績テーブルの該当行を更新し、実績テーブルの集計フィールドを再計算・更新する（継続/終了ダイアログは表示しない。記録中フローとは異なる操作のため）。画面遷移は行わず、この画面にとどまる。更新が完了したことをトースト通知で表示する（`CLAUDE.md` アーキテクチャ参照）。
- 「削除」ボタン: 確認ダイアログの上、この区間実績を削除し、実績テーブルの集計フィールドを再計算・更新した上で、実績詳細画面に遷移する。
- 「修正」ボタン押下後のトーストは画面下部中央に表示されるため、画面最下部の「戻る」「削除」ボタンと重ならないよう、画面の下側にトーストの高さ以上の余白を設ける。

### 前区間・次区間ボタン

画面最下部の左端のボタン（既存区間の修正では「戻る」、新規記録では「キャンセル」）と右端のボタン（既存区間の修正では「削除」。新規記録では無し。ただし修正時と配置を揃えるため領域のみ確保する）の間に、「前区間」「次区間」ボタンを配置する。区間の前後は、この実績の区間実績の開始時刻の昇順で判定する。

| ボタン | 表示条件 | 押下時の挙動 |
|---|---|---|
| 前区間 | 直前の（保存済みの）区間実績が存在する場合に表示する。最初の区間では非表示。新規記録の場合は、保存済みの区間実績が1件以上あれば表示する | 直前の区間実績の区間実績詳細画面（`/records/[recordId]/[periodId]`）に遷移する。新規記録の場合は、「キャンセル」ボタンと同様に確認ダイアログ（「はい」/「いいえ」）を表示し、「はい」で未保存の入力内容を破棄して保存済みの最後の区間実績に遷移する（「いいえ」ではこの画面に留まる） |
| 次区間 | 既存区間の修正で、直後の区間実績が存在する場合に表示する | 直後の区間実績の区間実績詳細画面に遷移する |
| 新区間（次区間の代わり） | 既存区間の修正で、保存済みの最後の区間であり、かつこの実績が記録中（記録中セッションの実績IDがこの実績と一致）の場合に、次区間ボタンの位置に表示する。デザインは「修正」ボタンと同じとする | 新規区間の記録を開始する（`/records/[recordId]/create` に遷移） |

- 記録終了している実績（記録中でない実績）の最後の区間では、次区間ボタンは非表示とする。
- 新規記録中（`/records/[recordId]/create`）は、次区間ボタンは表示しない。
- ボタンを非表示にする場合も、もう一方のボタンの配置は変えない（非表示のボタンも領域を確保したままにする）。

## 状態管理・永続化方針

- 対象の実績ID（`recordId`）はURLの動的セグメント（`route.params.recordId`）から取得する（記録中セッションのPinia storeは、記録中セッションの有無や対象実績IDの一致判定など、記録フロー自体の状態管理には引き続き使用する）。
- 新規記録時の未保存の入力内容（フォームの各フィールド、および「記録」ボタン押下〜継続する/終了するダイアログでの選択確定までの間の保存待ちデータ）は、コンポーネント内のローカルな状態（Vueの`ref`）として保持するのみで、PiniaやLocalStorageなど画面外への永続化は行わない。そのため、ページリロードやタブの閉じ直しを行うと入力途中のデータは失われる（記録中セッション自体の有無は`specs/top-screen.md`の方針どおりLocalStorageで復元されるが、区間実績の入力内容そのものは復元されない）。

## スコープ外・今後の検討事項

- 当選種別が複数回発生することはない。
